Forge platform / concept reference

The vocabulary, and where each word applies.

Forge runs on a small number of load-bearing concepts. Most confusion about the platform is really confusion between two of them. This deck names each concept, places it in the pipeline, and attaches the example that makes it concrete.

Twelve slides · use ← and →, the controls, or scrolling. Terms follow the Forge handbook; examples come from the documented Acme and Gusto demo scenarios.

01 / The spine

Eight rules the vocabulary exists to serve.

Every concept that follows is downstream of one of these. When a design question is genuinely hard, the answer is usually that two of these rules are in tension.

Compile. Don't configure.

Workflows are lowered into a sealed artifact, not assembled from runtime config.

Deterministic infrastructure. Intelligent execution.

Policy, queues, sandboxes, and approvals are predictable. Only the agent steps are not.

Extension over replacement.

Companies add packages. Nobody forks the core.

Adapters at every boundary.

No vendor type crosses into application or public code.

Prompts are versioned assets.

Content-addressed, semver-pinned, immutable once published.

Policies before permissions.

Authorization is evaluated, never inferred from wording.

Humans own the final decision.

AI recommends. A person approves anything that leaves the system.

Research before implementation.

Significant work starts with notes and an ADR, not a branch.

02 / The master flow

Two pipelines meeting at one seam.

Everything in Forge sits on one side of the artifact or the other. The left half is a pure function. The right half is stateful, durable, and allowed to touch the world.

The seam is the artifact. The compiler may not touch Redis, HTTP, an LLM, the filesystem, or the clock. The runtime may do all of those, but may never re-parse a manifest. Production refuses to execute anything that is not sealed and fingerprinted.

03 / Authoring concepts

What a company package actually writes.

Four things, all typed, all versioned. Nothing here imports an engine, a queue, or a provider.

Manifest

A workflow declared with defineWorkflow: id, semver, input and output schemas, nodes, and an explicit sideEffects[] list. The only path to a runnable graph.

Example useThe Acme campaign workflow marketing.campaign-brief declares a draft step, an approval gate, and exactly one publish side effect.

Prompt asset

A prompt registered with definePrompt — typed input, typed output, semver identity, immutable once published. Workflows reference it; the compiler pins the exact version.

Example useacme.marketing.draft.v1. Bumping it from 1.2.0 to 1.3.0 changes the artifact fingerprint, so the runtime will not pick it up until a recompile.

Skill

A named handler registered with defineSkill, declaring the capabilities it needs. The compiler checks those against the static policy closure before anything runs.

Example useA Gusto knowledge-base retrieval skill that requires benefits.kb.read and nothing else. Asking for more fails compile with WF_CAPABILITY_UNBOUND.

Policy pack

Authorization rules evaluated by the policy engine, versioned alongside the company package. Rules may narrow platform constraints; they may never widen them.

Example usebenefits.advice.regulated returns RequireApproval before any member-facing message on a regulated topic.

04 / Compile concepts

One pure function, five outputs.

The compiler proves static properties and then gets out of the way. Same manifest bytes plus same compiler version produce a byte-identical fingerprint, every time.

Compiler

Pure and deterministic. No network, no Redis, no LLM, no filesystem writes, no clock-dependent control flow.

Example useCompiler unit tests run with nothing else booted.

Forge IR

A Zod-validated discriminated union of node kinds and typed edges. Engine-agnostic on purpose — it is not shaped like any vendor graph.

Example useGolden IR snapshots are checked into CI for a linear, a branching, and a parallel workflow.

EnginePlan

An opaque branded type. Exactly one adapter may read it; it is never serialized to a client, and the runtime cannot introspect it.

Example useTypeScript brands make plan.nodes a compile error outside the lowering adapter.

Sealed artifact

IR, engine plan, and a public surface — input schema, output schema, approval gates, required capabilities — bound together and fingerprinted.

Example useThe operator UI reads the public surface to render gates; it never sees the plan.

Fingerprint

A hash over the canonical manifest, compiler version, pinned prompt versions, pinned policy versions, and IR schema version.

Example useWorkers cache a materialized graph keyed by fingerprint, so a prompt bump invalidates cleanly.

Diagnostic

A structured failure with a stable code, a path, and often a suggestion. Not a thrown string.

Example useWF_MISSING_APPROVAL fires when a declared side effect has no gate in front of it.

05 / IR node taxonomy

Eleven node kinds, and which ones can surprise you.

Determinism is a property of the node kind, not of the workflow. Only three kinds can produce a different result on identical input — which is exactly why the gates sit around them.

06 / Runtime concepts

Six nouns that carry the whole execution model.

These are Forge-owned entities, not vendor mechanisms wearing a Forge label. An operator never sees an engine interrupt or a queue job.

Run

One execution instance of one sealed workflow version, with a client-visible id that is unique and safe to retry against.

Example useTwo members asking the same benefits question produce two runs with separate audit trails.

Checkpoint

A durable snapshot taken at a well-defined boundary — node completion or interrupt. Survives a process restart.

Example useA worker crashing mid-run resumes from the last boundary rather than starting over.

Approval gate

The IR node that interrupts. Bound to a run, an action, an argument hash, and an expiry, so a decision cannot drift onto changed input.

Example useEditing the draft after approval invalidates the decision; it does not silently authorize the new text.

Approval record

The durable entity behind the gate: status, approvers, deadlines, the decision, any edit diff, and the policy id that triggered review.

Example useAn auditor reconstructs who approved what, when, and under which rule.

Resume payload

The typed decision that re-enters the graph — approve, reject, edit with a patch, or timeout — validated against that gate's schema.

Example useAn edit-then-approve decision carries the amended fields and continues with the edited state.

ForgeJob

A schema-validated queue message. Execute, resume, or cancel. A vendor job object never reaches domain code.

Example useWorkers re-validate every payload before calling the runtime, so a malformed message fails at the edge.

07 / Run lifecycle

Waiting on a human is a state, not a held lock.

The most consequential design decision in the runtime is what happens when a workflow needs a person. Forge treats that wait as durable state, so human time never consumes a worker.

PENDING

The run exists; the execute job has not been picked up yet.

RUNNING

A worker is actively executing, or a bounded transport retry is in flight.

AWAITING_APPROVAL

A durable interrupt. The job is acked, the worker is released, and the wait is persisted.

RUNNING

A separate resume job picks the run back up with the typed decision.

SUCCEEDED

Terminal. Output validated against the artifact's output schema.

FAILED

Terminal, with a structured error code and the node that produced it.

CANCELLED

Terminal, by explicit cancel or by policy timeout.

RETRYING

Not a separate state. The run stays RUNNING and the attempt counter increments.

The rule that makes it work: a worker must never hold a queue lock across human time. On interrupt the runtime checkpoints, acks the job, and releases the worker. Resume arrives later as an entirely new job.

08 / Ports and adapters

Every boundary is an interface someone else implements.

Dependencies point inward. The application layer knows only port interfaces; concrete adapters are bound in exactly two places, and no vendor type travels upward.

PortLayerWhat it abstracts
GraphEnginePortContract

Materializing and executing an opaque engine plan; start and resume.

QueuePortContract

Transport and worker scheduling. Not the workflow engine.

CheckpointStorePortContract

Forge-level checkpoint metadata. Engine blobs stay inside the adapter.

ApprovalPortContract

Request, decide, and list human gates as first-class records.

ProviderPortContract

Agent and model sessions, always inside a sandbox workspace.

PolicyPortContract

Allow, deny, or require approval before a gated step. Fails closed.

SandboxPortContract

Disposable compute for tool and code execution.

Run and step spans plus structured audit events.

ClockPort, IdPortContract

Time and identity, injected so tests stay deterministic.

Composition roots are the only wiring points. The API app and the worker app bind real adapters; integration tests bind fakes. A fitness test fails the build if a public package reaches a vendor library.

09 / Distinctions that matter

Six pairs people collapse, and shouldn't.

Nearly every design argument about Forge turns out to be one of these six. Naming the pair usually settles it.

Transport retry is not workflow retry

A Redis blip or a crashed worker is infrastructure, retried inside the queue adapter. A provider timeout is a workflow concern, governed by the node's declared retry policy and checkpointed before each attempt.

A judge is not a policy

A judge scores an artifact and emits a verdict with reasons and evidence. It recommends. Policy decides. A judge that errors returns review and escalates — it never grants a permission.

A prompt is not a capability

Prompt text can ask for anything. It expands nothing. The capability set is fixed at compile time and enforced at runtime, so an injected instruction cannot authorize an effect that policy denies.

An interrupt is not an approval

An interrupt is an engine mechanism the lowering adapter maps internally. An approval is a Forge record with approvers, a deadline, an audit trail, and a policy reason. Operators only ever see the latter.

The compiler is not the runtime

The compiler is pure and may not touch the world. The runtime is stateful and may not re-parse a manifest. Every ambiguous responsibility resolves by asking which of those two constraints would break.

A request is not permission

Work arriving through a connector carries a claim about who is asking. Authorization comes from the authenticated boundary and the policy evaluation — never from a field in the request body.

10 / Worked example

One run, touching every concept in order.

The Acme campaign scenario, traced end to end. Each step names the concept it exercises, so the vocabulary lands against something concrete.

  1. A launch brief arrives from a connector and is normalized into a workflow request — title, evidence, source, principal, classification, and an idempotency key.

  2. The API authenticates the caller, validates the shape, and checks the workflow against an allowlist. Identity comes from the boundary, not the payload.

  3. The runtime loads the sealed artifact for that workflow version. Nothing is parsed or compiled at execution time.

  4. An agent node drafts copy using a pinned prompt asset. The output is validated against the node's declared schema before it can influence a branch.

  5. A judge node scores the draft and returns a verdict with reasons and evidence. It recommends; it does not decide.

  6. A policy check evaluates the trusted actor, source, classification, and action hash. Publishing externally resolves to RequireApproval.

  7. The engine reports an interrupt. The runtime writes a checkpoint, creates an approval record, sets the run to AWAITING_APPROVAL, and acks the job — releasing the worker before human time begins.

  8. A marketing lead sees the draft, the citations, the policy reason, and the exact parameters of the proposed action, then approves. The resume payload is validated against that gate's schema.

  9. A fresh resume job re-enters the graph. The approval is bound to this run and this action hash, so it cannot authorize anything else.

  10. The declared side effect is recorded, then dispatched through the durable outbox under a stable operation key — exactly one publish, even across a restart.

  11. The run reaches SUCCEEDED. Spans, the policy decision, the judge verdict, and the approval record reconcile into one audit trail.

Boundary / what belongs where

The core stays generic. The company package stays specific.

A company package owns

Domain vocabulary, workflows, prompt assets, skills, policy packs, fixtures, intake profiles, and presentation. It narrows the public contracts for its domain and never imports a private runtime internal.

The core owns

Compilation, workflow execution, approval binding, durable effects, policy evaluation, sandboxing, and observability. The same controls serve every company package; only configuration differs.

The proof that this separation is real: one runtime executes both the Acme demos and the Gusto domain workflows, and the difference between them is which packages are installed — not which engine was rewritten. If a company concept ever needs a core change to work, that is the signal to write an ADR rather than a branch.
